# Milestone 9 requirement-to-test matrix

This matrix records concrete evidence and remaining gaps for the Milestone 9 testing requirements. API integration coverage currently lives in `automation.integration.test.ts`, worker checks use injected network adapters, and browser tests exercise the rendered Reliability section. No reliability test performs an external network request.

| Requirement | Previous evidence | Completion evidence |
| --- | --- | --- |
| Permissions, suspended users, tenant isolation, reference isolation | Existing workspace authorization tests are generic | Direct route tests cover owner/admin/member/suspended boundaries, archived mutation denial, cross-workspace SLO history and relationship denial, and replica-set service archival races against valid SLO, monitor, dependency, and relationship writes. Both resource-first and archive-first outcomes leave no active dependent references. |
| Slugs, dependency cycles and traversal limits | Contract-only slug/self-edge checks | Replica-set API tests cover indirect cycles, ten-edge depth enforcement, and bounded impact results. The schemas cover slug and pagination bounds. |
| SLO validation, immutable versions, missing data, compliance and burn rates | Shared schema tests only | API/service integration tests cover version history, empty windows, exact budgets, short/long windows, late samples, and immutable evaluations |
| Signed ingestion authentication and limits | No direct tests | API integration tests cover valid raw HMAC, invalid signature, time tolerance, replay, body/rate/batch/metadata bounds, malformed and cross-tenant samples, concurrent idempotency, and redacted failures |
| Alert and automation lifecycle | Concurrent evaluation proves one fingerprint, one escalation, one breach event, and one budget event | Deterministic breach-first/recovery-second and recovery-first/stale-breach-second orderings prove matching-alert resolution, missing-data continuity, stale-write fencing, duplicate-event denial, and immutable version/window snapshots. |
| Monitor transport security | URL helper tests covered only basic private addresses | Worker integration tests cover IPv4/IPv6 denial, redirect/rebinding/timeout/body limits, encrypted secret rotation/redaction, and injected adapters |
| Durable monitor execution | Atomic claims, overlap denial, stable identity, lease recovery, endpoint/infrastructure classification, disabled/archive denial, five-attempt exhaustion, bounded deterministic jitter, dead letter, role checks, concurrent administrative retry, and retry-versus-worker claim are covered | Transition-first disable/archive and retry-first then disable orderings prove transactional eligibility checks and the immediate execution fence; no fake-network call, duplicate run, alert, or outbox event survives an invalidated retry. |
| Realtime audiences and reconnect | Cluster tests already cover coordination recovery, suspended-user revocation, and duplicate presence/subscription prevention | A two-gateway test covers all twelve reliability names, workspace/private audiences, owner/admin-only failure hints, tenant denial, and payload redaction. REST records remain authoritative because hints carry empty invalidation payloads. |
| Metrics | No previous reliability aggregation tests | Replica-set API tests cover lifecycle, criticality, owner coverage, compliance/budgets, breach history, monitor success/latency/failure duration, alert and incident grouping, overlapping/open incidents, mean resolution, archived history, risk ranking, empty state, 90-day bounds, and tenant isolation. |
| Frontend workflows and accessibility | Catalog/detail, lifecycle, dependency table, unknown state, relationships, execution history, offline state, member restrictions, and write-only secrets are covered | Rendered workflow tests perform SLO editing, burn-history expansion, impact loading, dead-letter retry, offline-to-reconnecting REST refresh, visible API failure with keyboard retry, and one-shot secret rotation. The form clears the newly entered secret and never restores stored secret material. |

The pre-existing helper and contract tests remain useful but are not counted as integration evidence where the original requirement calls for transactions, authorization, concurrency, worker recovery, or rendered workflows. Every Milestone 9 matrix row now has direct contract, integration, worker, cluster, or rendered-workflow evidence; none relies only on a shallow render assertion.
